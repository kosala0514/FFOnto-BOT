FFOnto: Description back to ToC

Three layers: world, data and claims

The central design decision is to keep three kinds of statements apart. A model that says "smoke, 0.73" makes a claim about a data record; it does not establish a fact about the world. Keeping the layers apart lets the knowledge graph store several conflicting claims, compare them across modalities, and trace every derived conclusion back to the model, the threshold and the record it came from.

Design principles

  1. Separate world, data and claims (Figure 1). Model outputs are ffonto:ModelObservations with a confidence, the threshold used and the model that produced them (PROV-O).
  2. Fine-grained kinds and values are SKOS concepts, not classes. "Is a Pulaski in use?" is answered with the generic ffonto:hasKind and the concept ffontov:Pulaski (narrower than ffontov:HandTool). A new tool, state or hazard is one new concept in the vocabulary; the schema does not change.
  3. Derived knowledge comes from rules. Detections, weather conditions, cross-modal conflicts and hazards are computed by SPARQL rules, so changing a threshold never means editing data.
  4. Reuse standards by IRI: ffonto:ModelObservation ⊑ sosa:Observation, ffonto:CaptureDevice ⊑ sosa:Sensor, ffonto:FireEvent, ffonto:Site, ffonto:SceneEntity ⊑ sosa:FeatureOfInterest, ffonto:DataRecord ⊑ prov:Entity, ffonto:Model ⊑ prov:SoftwareAgent.
  5. Every term is needed by a competency question; terms that no CQ query uses are not part of the core.

Competency questions

Each CQ is implemented as a tested SPARQL query. The ForestFire-VQA questions map onto these CQs, so a small set of queries answers the whole dataset.

Example

An image record with a smoke-classifier observation and one scene entity extracted by a vision-language model:

ffd:img081  a ffonto:ImageRecord ;
    ffonto:aboutEvent      ffd:event-demo081 ;
    ffonto:hasObservation  ffd:img081-obs-smoke .

ffd:img081-obs-smoke  a ffonto:ModelObservation ;
    ffonto:predictedClass   ffontov:Smoke ;
    ffonto:confidence       0.73 ;
    ffonto:usedThreshold    ffd:threshold-smoke ;          # 0.60
    prov:wasAttributedTo ffd:model-fire-smoke-classifier .

ffd:img081-entity1  a ffonto:SceneEntity ;
    ffonto:hasKind  ffontov:Firefighter ;
    ffonto:wears    ffontov:Helmet ;
    ffonto:performs ffontov:ApplyingWater .

"Is the firefighter wearing gloves?" then becomes a query over ffonto:wears, and "Which PPE is missing?" compares ffonto:wears with the background knowledge ffontov:Firefighter ffonto:requiredPPE … in the vocabulary.

Validation

The ontology is checked with ROBOT (OWL 2 DL profile, report), the HermiT reasoner (consistency on schema and data, plus negative tests that must be detected as inconsistent), OOPS!, SHACL shapes on the data, and a pytest suite that runs every CQ query against fixed test data.
