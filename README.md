# FFOnto v2 — CQ-driven, multimodal starter kit

A small, testable rebuild of the Forest Fire Ontology, scoped to the ForestFire-VQA competency
questions (CQ01–CQ26). It turns your **image JSON, audio JSON, weather CSV** and **scene graphs
extracted by a vision-language model (VLM)** into one knowledge graph. That graph answers every CQ with a SPARQL query.

```
ontology/
  ffonto-core.ttl        23 classes, 39 object + 57 datatype properties (the schema)
  ffonto-vocab.ttl       374 SKOS concepts: kinds, states, activities, PPE, values, hazards, actions, ecology
  danger-rules.ttl       weather/FWI threshold rules stored as data (PLACEHOLDER values!)
  ffonto-shapes.ttl      SHACL data-quality checks (missing metadata, alert readiness, missing PPE)
context/
  ffonto.context.jsonld  JSON-LD @context: maps every JSON/CSV field to an ontology term
data/
  raw/                   your two real records + fixture records (fixture_* = invented test data)
  scenes/                scene graphs a VLM would produce (hand-written examples)
  jsonld/                generated by lift.py
rules/   R00–R07         SPARQL CONSTRUCT rules (detections, caption tagging, danger, conflicts, hazards)
queries/ CQ01–CQ26       one SPARQL query per competency question (+ CQ07b)
prompts/                 VLM scene-extraction prompt, generated from the vocabulary
scripts/
  lift.py                raw data → JSON-LD → RDF  (data/kg.ttl)
  run_cqs.py             rules + SHACL + all CQ queries → results/
  make_prompt.py         regenerates the VLM prompt from the vocabulary
```

## 1. Run it

```bash
pip install -r requirements.txt          # rdflib, pyshacl
python scripts/lift.py                   # -> data/jsonld/*.jsonld, data/kg.ttl
python scripts/run_cqs.py                # -> results/report.md, results/CQxx.csv, results/shacl_report.txt
python scripts/run_cqs.py CQ05 CQ24      # run selected CQs only
```

Open `results/report.md` to read every answer. `data/kg_inferred.ttl` holds the data plus everything the rules derived.
You can open it in Protégé or load it into GraphDB or Apache Jena Fuseki together with the `ontology/` files.

> These files were checked offline: every Turtle file parses, and every term used in the rules,
> queries, context and data is declared in the ontology or vocabulary. They have **not yet been executed with
> rdflib**. If a query fails on your machine, the error is printed next to the CQ in `report.md`;
> it is usually a one-line fix.

## 3. Design in one picture

```
            WORLD                         DATA                               CLAIMS (model outputs)
   ffonto:FireEvent ◄──ffonto:aboutEvent── ffonto:ImageRecord ──ffonto:hasObservation──► ffonto:ModelObservation
                                     ffonto:AudioRecord                           ├ ffonto:predictedClass  ffontov:Smoke
                                     ffonto:WeatherRecord (direct values)         ├ ffonto:confidence      0.73
                                          │                                    ├ ffonto:usedThreshold → 0.60
                                          │ ffonto:hasCaption → ffonto:Caption       └ prov:wasAttributedTo → ffonto:Model
                                          ▲
                         ffonto:describesRecord
                                          │
                               ffonto:SceneDescription ──ffonto:depicts──► ffonto:SceneEntity
                               (VLM output)                           ├ ffonto:hasKind   ffontov:Firefighter   (SKOS)
                                                                      ├ ffonto:wears     ffontov:Helmet
                                                                      ├ ffonto:performs  ffontov:ApplyingWater
                                                                      ├ ffonto:hasState  ffontov:Scorched
                                                                      └ ffonto:near / advancingToward / protects …
   DERIVED by rules:  ffonto:detectedClass · ffonto:mentionsConcept · ffonto:hasCondition · ffonto:ModalityConflict · ffonto:Hazard
```

Five rules keep the ontology small:

1. **Separate the world, the data and the claims.** A model saying "smoke 0.73" is an *observation* with confidence, provenance and a threshold, not a fact about the world.
2. **The fine-grained vocabulary is SKOS, not schema.** "Is a Pulaski in use?" uses the generic `ffonto:hasKind` + `ffontov:Pulaski` (a narrower concept of `ffontov:HandTool`). Adding a new tool means adding one concept, with no new class or property.
3. **Derived knowledge comes from rules.** Hazards, detections, conflicts and weather conditions are computed (`rules/`), so changing a threshold or rule never means editing data.
4. **Reuse standards.** The ontology builds on SOSA (observations), PROV-O (provenance) and Dublin Core (licence).
5. **Every term must be used by a CQ query.** If no query needs a term, it does not belong in the core.

## 4. Everyday tasks

**Add a new dataset question.** Find its CQ template in `FFVQA_CQ_mapping.xlsx`. If the vocabulary already has the concept,
nothing changes: the existing query answers it. Otherwise add one SKOS concept to `ffonto-vocab.ttl`
(under the right `skos:broader`), then re-run `make_prompt.py` so the VLM can produce it.

**Process real images.** Run your VLM with `prompts/scene_extraction_prompt.md` on each image and save the JSON to
`data/scenes/`. `lift.py` warns about any term the VLM invents that is not in the vocabulary, and skips it.

**Link modalities.** Give every record of the same incident the same `event_id`. The weather CSV has an extra
`event_id` column for this. Fill `capture_time_utc` and `crs`; SHACL reports where they are missing.

**Tune the risk logic.** Edit the thresholds in `ontology/danger-rules.ttl` (they are placeholders; cite real sources),
and the hazard rules in `rules/R06_scene_hazards.rq`. Each `UNION` branch there is one rule.

**Answer general-knowledge questions** (the 291 "General Knowledge" rows). These are out of scope for the KG.
Answer them with retrieval over documents (RAG), and use the KG only for grounding definitions (`skos:definition`).

## 5. Known limitations

- Scene facts are only as good as the VLM output. Keep `human_validated` and spot-check a sample.
- Entity confidences from the VLM are not stored yet. Scene-level attributes are modelled as observations, so a confidence can be added there.
- Geometry is stored as WKT text. Switch to GeoSPARQL (`geo:hasGeometry`) if you need spatial queries.
- The relations "near" and "advancing toward" are frame-relative judgements, not measured distances.
